# ADR-0001: модульный monorepo вместо ранних микросервисов

- Статус: принят
- Дата: 2026-11-04

## Контекст

Sentinel содержит ingestion, API, доставку уведомлений, публикацию attestations и UI. Эти процессы имеют разные профили отказа, но на этапе foundation отдельные репозитории и независимые релизы увеличили бы операционную сложность без доказанной пользы.

## Решение

Хранить приложения и библиотеки в одном pnpm/Cargo monorepo. Границы задаются package API и процессами, а не сетевыми вызовами. PostgreSQL остаётся общей точкой согласованности. Разделение на независимо развёртываемые сервисы возможно после появления измеримых требований к масштабированию.

## Последствия

- Единая атомарная CI-проверка контрактов и миграций.
- Проще replay и локальная разработка.
- Следует избегать скрытого импорта внутренних файлов между packages.
- Позднее выделение сервиса потребует версионирования его API и событий.
